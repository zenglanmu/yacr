# yacr v0.1.19

Source: `CI build layers` run
[45650536568](https://github.com/zenglanmu/yacr/actions/runs/45650536568) (tag `v0.1.19`); the assets are attached by
`.github/workflows/publish-release.yml`.

Released: 2026-11-25

> v0.1.18 was built but never published (withdrawn after a performance problem).
> This release supersedes `v0.1.17` and contains everything from v0.1.18 plus the
> application-domain work and the renderer memory fix in this round.

## What changed

### Application domains

- **Four work surfaces, one React tree.** Documents gain an `application_domain`
  property (`cad2d | bim | concept | mechanical`), derived from the import source:
  DWG/DXF/DGN → 2D drafting, IFC/RVT → BIM, SKP → concept modelling, STEP →
  mechanical design. Unknown sources declare no domain and stay on `cad2d`. The
  domain is written to `document.json`; switching changes only the document header
  (one revision) and converts no data.
- **All four domains are wired**, no longer placeholder cards:
  - `cad2d`: the AutoCAD-referenced drafting ribbon (File/Home/Insert/Annotate/
    Parametric/View/Manage/Output/Add-ins) and command line — the existing full UI.
  - `bim`: the Revit-referenced nine-tab ribbon and left tray (Properties/Project
    Browser/Visibility/BIM browse/Schedules/action hints), no command line; the
    six BIM view presets go through typed `cad_set_view`.
  - `concept`: the SketchUp-referenced menu bar, left tool set and right default
    tray; Space selects, the official single-key table works, and the status-bar
    Measurements box uses real host tool parameters instead of fake inputs.
  - `mechanical`: a fixed initial subset of the SolidWorks-referenced ribbon plus a
    left FeatureManager / PropertyManager / ConfigurationManager; no command line,
    numeric entry stays in the real status-bar tool parameters.
- **Switching**: the `DOMAIN` command (bare opens the switcher; `DOMAIN <id>`
  writes the document when one is open and only previews otherwise) shares one
  switcher with the “Application domain” row in every profile’s File menu/page.
  Unknown tokens are refused as `domain.unknown`; an old/unknown host token falls
  back to the most complete `cad2d` with a notice naming the original token, while
  the document value and its data stay unchanged.
- **Per-domain themes**: `<html data-domain>` selects the UI tokens; the renderer’s
  canvas background still follows `theme` (dark/light). Persisting a theme per
  domain (`ui.theme.<domain>`) is **not implemented yet**.
- **Structural transcription, not imitation**: tab/menu/tool order is recorded as
  contract fixtures from the official manuals; icons and copy are our own. Tools
  without a kernel are disabled/pending rows with a stable reason, never clickable
  fake buttons. Plugins can extend menus/tool groups/trays declaratively through
  `@yacr/plugin-api`’s `api.ui.register` (client-local; no JSX/HTML injection).

### Concept modelling and mechanical

- `EXTRUDE` turns a bounded closed planar profile into a new exact solid: a single
  LINE loop, a closed all-line `LWPOLYLINE`, or a full circle, in +Z/-Z with the
  distance from Measurements. The profile stays in place; one transaction, one
  undo step. Profiles with arc walls, holes/multiple loops, draft and arbitrary 3D
  planes are refused by name.
- `PRESSPULL` moves one face of an existing exact solid (signed distance) through
  the same modeler seam and undo path; turning a 2D profile into a solid still uses
  `EXTRUDE`. `FOLLOWME`, multi-face/continuous push-pull and drag-driven distance
  are not implemented.
- Dimensional input is wired to real tool parameters: LINE length/angle, RECTANG
  width/height, CIRCLE radius, ROTATE angle, MOVE distance, SCALE factor, OFFSET
  distance, EXTRUDE/PRESSPULL distance; 0 means unset.
- The `mechanical` FeatureManager tree comes from the read-only host read
  `cad_mechanical_tree`: features from `tables/features.json` in order
  (`schema_only`, no evaluator yet) followed by `Body3d` rows (`ready`/
  `unavailable`), truncated at 1024 rows with real `total`/`truncated`. It does not
  evaluate or rebuild geometry; carriers without the seam refuse by name as
  `unsupported-runtime: mechanicalTree`.
- **Not implemented**: feature evaluation/geometry propagation, revolve/sweep/loft/
  shell/hole, sketch constraints and smart dimensions, assembly mates, drawing
  views, materials and appearances, the BIM element kernel/view-and-sheet
  tree/family editor. The UI keeps them pending and the command layer refuses them
  by name.

### BIM / Revit-style workspace

- The Revit-style domain ribbon and left tray landed in stage 4: File page
  (New/Open/Save/Export/Plot/Close), Architecture/Structure/Insert/Annotate/
  Analyze/Massing & Site/Collaborate/View/Manage. The tray can be hidden as a whole
  and sits by domain (BIM left, concept right).
- `cad_set_view` is a typed channel: an absolute `eye/target/up/projection/mode`, or
  host-fitted `overview`/`plan`/`front`/`back`/`left`/`right` against the active
  space. A real change records one `ZOOM PREVIOUS` step; an empty active space is
  refused as `view.set.empty`; 3D presets on `dom-canvas` stay disabled by host
  profile.
- BIM query remains the single `cad_bim_query` (paged rows plus facet summary in
  one answer); the property panel and BIM browse reuse existing data instead of a
  second query path.

### Rendering and memory

- The performance/memory problem behind the v0.1.18 withdrawal is fixed:
  `fixtures/complex-test.dwg` (≈725K expanded entities) on this Linux/Wayland +
  P620 host now holds a steady tree RSS of about **1.55 GB (was ≈3.22 GB)** with a
  peak of about **2.45 GB (was ≈4.07 GB)** and ≈1.07 GB of GPU memory. A committed
  CPU scene copy is released after a full upload (metadata stays, rebuild is
  possible), and staged uploads are submitted per tick instead of accumulating a
  whole scene.
- Universal GPU storage is the default (no duplicated “pulled” vertex organisation)
  and the VRAM budget defaults to **80%** (10–80 adjustable, leaving room for the
  compositor/WebView). A persisted 81–100 setting is lowered to 80 at startup with
  a diagnostic; out-of-range live writes are still refused, never clamped.
- Existing presentation is retained from the v0.1.17 baseline: isometric default,
  centred FIT, PBR textures/IBL/MSAA, surface-boundary wireframe, and real 3D
  camera presets in the headless `render` command.
- **Evidence boundary**: the memory figures are one bounded run on the Linux/
  Wayland host with a real GPU (`complex-test.dwg`). RSS reclamation and real
  device-loss recovery on Windows/macOS/Android/Web are **NOT VERIFIED**; this is
  not a general performance promise or a GPU acceptance.

### Command coverage

- **289** commands are complete and **690** partial (the implemented total stays
  979/981); the other 2 (MEASURE, TRACE) are counted as same-name-different-meaning.
  Unsupported options are still refused by name. Interactive prompts, the system
  clipboard, multiple documents, plotters/CTB/STB and 3D assemblies are global
  scope, not per-command gaps.

### Block attributes and reference editing

- `ATTDEF` is a real block member and attribute values live on the `INSERT` row;
  they persist with the document and round-trip through DXF/DWG. `ATTEDIT`/
  `ATTIPEDIT`/`GATTE`/`EATTEDIT`/`ATTSYNC`/`ATTREDEF`/`BATTORDER`/`ATTDISP` edit
  values, order and visibility, and inserted values are drawn according to
  `ATTDISP`.
- `REFEDIT`/`-REFEDIT`/`REFSET`/`REFCLOSE` edit references and block members in
  place and write the result back.

### Groups, named views and action recorder

- Groups (`GROUP`/`-GROUP`/`UNGROUP`/`GROUPEDIT`) moved into the document table
  `tables/groups.json` (`.ymodel` minor 17) and round-trip as `AcDbGroup` in
  DXF/DWG; names with spaces are addressed with quotes.
- Named views (`VIEW`/`-VIEW`/`VIEWGO`/`NEWVIEW`) moved into `tables/views.json`
  (minor 18). `NEWVIEW` accepts a name or a `WINDOW` rectangle, and the DXF/DWG
  `VIEW` table is read and written. Continuous pan/orbit gestures enter the
  navigation history; `VIEWBACK`/`VIEWFORWARD` remain partial.
- The action recorder works: `ACTRECORD`/`ACTSTOP`/`ACTUSERINPUT`/`ACTUSERMESSAGE`/
  `-ACTUSERMESSAGE`/`ACTMANAGER` record replayable macros (versioned JSON,
  ADR-0056), and the Manage panel drives the session commands directly.

### Layers, viewports and 2D editing

- `LAYLCK`/`LAYULK`/`LAYFRZ` accept paper space and block picks, and `LAYFRZ`
  writes `Vpfreeze`; `LAYCUR`/`LAYMCH`/`-LAYMCH`/`LAYMCUR` extend to paper layouts
  and top-level `INSERT`. `LAYERPMODE` persists in the document header, and
  `LAYERP`/`LAYWALK` snapshot restore and wildcard filters are complete.
- `VPMAX`/`VPMIN`, `VPORTS` standard configurations and `VPSYNC` master-viewport
  sync work; `LAYERSTATE`/`LAYERSTATESAVE` remain session snapshots (no DWG named
  layer-state table or dialog).
- New/completed: `CHPROP`, `BREAKATPOINT`/`FLATTEN`, `TEXTALIGN`, `TCIRCLE`,
  `DONUT`, `HATCHGENERATEBOUNDARY`, `ADDSELECTED`, `GETSEL`, `MEASUREGEOM VOLUME`,
  `CENTERMARK`/`CENTERLINE`, `HATCH`/`-HATCH` (including `.pat` files),
  `HATCHEDIT`, `IMAGEATTACH`, `MIRROR` (`MIRRTEXT`), `EXPLODE` (`EXPLMODE`),
  `XPLODE`, `CDORDER`, `BTRIM`/`BEXTEND`, `DIMROTATED`, `DIMREASSOC`.
- `FINDINCLUDE`/`FINDMATCH`, `MULTIPLE`, `TFRAMES`, `TEXTSCR`/`GRAPHSCR`,
  `TRAYSETTINGS` and `-PURGE` are real session switches; the reporting set
  `BCOUNT`, `DBLIST`, `JULIAN`, `ALIASEDIT` and `PAGESETUP`/`-PAGESETUP` gained
  their read/write paths.

### Units, time and document info

- The stored `UNITS`/`-UNITS` formats (length/angle format, precision, base angle,
  direction) now drive the status-bar coordinates, command echo/log and measurement
  diagnostics; `$INSUNITS` insertion scaling and the UNITS dialog stay global
  scope.
- `.ymodel` records the creation/last-updated times read once at save and reads
  them back on open; `TIME`/`EDITTIME` report the stored values (elapsed time,
  timers and active editing time remain NOT TRACKED).
- `DWGPROPS` writes real document summary and custom properties; `SYSVDLG` supports
  `SAVE|RESTORE <file.json>` (versioned `yacr.sysvar`); `ACADINFO` reports the real
  target OS/architecture, units/precision and application domain.

### Saving, exporting and carriers

- `SAVE` always writes `.ymodel` on Linux/Windows/macOS/Android (atomic replace,
  previous version kept as `.bak`; Android only when the provider supports a
  backup, otherwise `save.no_backup`), and other formats go through `EXPORT`.
- Web/`dom-canvas` now has a real `.ymodel` archive: `SAVE` encodes it in the wasm
  session and starts a browser download (`download://<seq>/<name>`); every save is
  a new download — no in-place overwrite, no `.bak`, no recovery snapshot. Without
  an archive it still refuses by name.
- macOS handles `RunEvent::Opened`: a Finder double-click/“Open With” launch queues
  the file in a bounded FIFO and loads it through the same funnel as `--open`
  instead of stopping at the welcome page. **A real macOS double-click remains NOT
  VERIFIED.**
- Android file associations match the sources (28 mimeTypes / 48 pathPatterns,
  including `.rvt`); this round rebuilt the debug APK and checked it with `aapt2`.
  “Open with” on a device is still not accepted.
- Tianzheng/Explorer proxies (ADR-0030 P0): wall/opening/text/block-insertion
  semantics are written to `tables/vendor.json` (minor 12) and recomputed on reopen
  by `YANS`; the `openProgress`/`documentReady` gates apply before `SAVE`/`EXPORT`/
  `PLOT`. The remaining P1 class semantics and the copy hook are still missing.

### Compatibility

- **`.ymodel` files saved by v0.1.16 and earlier cannot be opened**: entries are
  zstd frames and `format.read` must be 2, so old archives are refused as
  `ymodel.unsupported_version`; re-import the source files.
- `.ymodel` uses the lowest minor the document needs: application domain 13, block
  attributes 14, `Text.mirrored` 15, 2D constraints 16 (planned), groups 17, named
  views 18. Documents without those contents still write 4/5/7/8/9/10/11/12.
  Builds up to v0.1.17 cannot read archives with minor 14+ tables/fields and refuse
  them as `ymodel.unsupported_minor`.
- The bounded 2D constraint solver (ADR-0054) is only an accepted design; P0 has not
  started, constraint commands are still refused by name and are not part of this
  release.
