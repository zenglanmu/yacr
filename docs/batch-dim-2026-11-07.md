# 2026-11-07 dimension batch: DIMSTYLE / DIMTEDIT / DIMEDIT / DIMOVERRIDE / DIMREGEN / DIMDISASSOCIATE / QDIM (partial)

Status: **contract-level implementation only**. No GUI run, no real DWG, no GPU
and no frontend test run were performed for this batch. Everything below is
synthetic in-process evidence unless explicitly marked otherwise.

This batch implements the ten AutoCAD 2026 2D dimension commands below by
reusing the existing `cad-domain` `Dimension`/`DimensionGeometry` entity, the
`cad-db` `dim_styles` table, and the existing dimension creation/edit helpers.
No second document authority and no second geometry path were introduced.

## Wiring

Each command has a `CommandId`, a `COMMAND_TABLE` row (except `-DIMSTYLE`,
which is an alias), an `Application::execute` arm, work-mode classification
where it writes, a UI catalog row, gating (argument spec / selection minimum),
and both i18n locales.

* `CommandId`: `DimStyle`, `DimTextEdit`, `DimEdit`, `DimOverride`, `DimRegen`,
  `DimDisassociate`, `QDim`, `DimJogLine`, `DimBreak`.
* `COMMAND_TABLE`: `DIMSTYLE`, `DIMTEDIT`, `DIMEDIT`, `DIMOVERRIDE`, `DIMREGEN`,
  `DIMDISASSOCIATE`, `QDIM`, `DIMJOGLINE`, `DIMBREAK`.
* `COMMAND_ALIASES`: `-DIMSTYLE` → `DIMSTYLE`.
* Typed arguments: `cad-ui-core::session::dim_arguments` with selectors in
  `ARGUMENT_SELECTORS`; dispatches `CommandPayload::Dimension`.
* Application: `cad-app::app_drawing::dimension_edit`.
* Work-only (write): `DimTextEdit`, `DimEdit`, `DimOverride`, `QDim`. The other
  five can never write, so Viewer mode can reach their read-only report/refusal.
* Docs: long-form contract in `crates/cad-app/src/command_id/dimension_edit.rs`.

## Per-command implementation and exact boundaries

### DIMSTYLE / -DIMSTYLE

Typed forms:

* `DIMSTYLE LIST` — one `dimstyle.entry` diagnostic per stored style (name, id,
  text height, arrow size, `DIMDLI`). Read-only: no revision bump, no `ChangeSet`,
  no history. A drawing with no style rows reports `dimstyle.empty`.
* `DIMSTYLE CURRENT` — reports the style creation resolves, which is fixed to
  `Standard` by ADR 0017 B.3 (`dimstyle.current`); a missing `Standard` is
  `dimstyle.current_missing`. Read-only.
* `DIMSTYLE SET <name>` — named refusals only:
  * unknown name: `dimstyle.unknown`;
  * existing name: `dimstyle.set_unavailable` — the live
    `cad_db::DrawingDatabase` exposes read-only `dim_styles()` /
    `dim_style_by_name()`; only `DrawingDatabaseBuilder::insert_dim_style` can
    add a row, and there is no post-import mutate/delete API.
* Bare `DIMSTYLE` / `-DIMSTYLE`: `dimstyle.needs_option`; no default option.

`-DIMSTYLE` is not a second `CommandId`: it is an alias, so it shares the same
grammar and path. `DIMSTYLE SET` never writes, so the command as a whole stays
Viewer-legal; a Viewer `SET` therefore gets the capability refusal rather than a
mode refusal.

**NOT IMPLEMENTED**: real DIMSTYLE creation/modification, the style dialog,
`DIMSTYLE APPLY`, per-style overrides (`DIMSTYLE <name>` as an override
session), style-table delete/rename, and any persistence of `SET`.

### DIMTEDIT

`MOVE <x> <y>` sets `DimensionDefinition::text_middle` (group 11) to the typed
drawing-plane X/Y, with Z taken from the dimension's own definition plane (never
typed, so the text stays in plane). `ROTATE <degrees>` sets
`DimensionDefinition::text_rotation` (group 53) in radians with no
normalisation; `0` is the "derive" sentinel and returns the derived rotation.
`RESET` restores both sentinels. It does **not** clear the text override (that is
`DIMEDIT RESET`).

The command requires **exactly one** directly addressable selected dimension.
Each real change rebuilds the entity through
`DimensionGeometry::synthesized` from the mutated definition, the stored style
snapshot and the stored text override, and writes it with one `update_entity` in
one transaction / one undo step. A no-change run reports `dimtedit.unchanged`
with no transaction.

Refusals (nothing written, no history): `dimtedit.payload`,
`dimtedit.selection` (not exactly one), `dimtedit.duplicate`,
`dimtedit.not_addressable` (block member/sub-element), `dimtedit.target_missing`,
`dimtedit.not_dimension`, `dimtedit.bad_position`, `dimtedit.bad_rotation`,
`dimtedit.degenerate`.

Declared consequence: `cad-domain` keeps the display source private and no
constructor rebuilds an imported anonymous-block picture from a mutated
definition (the same limitation the dimension grip drag declares). A successful
edit therefore re-synthesizes the display; the stored definition still drives
the measurement, so no number is invented.

**NOT IMPLEMENTED**: AutoCAD's `Left`/`Right`/`Center`/`Home` text justification
and the oblique/angle dimension-line edit.

### DIMEDIT

`TEXT <override>` stores the string verbatim as `text_override` (group 1). `<>`
is the measurement placeholder understood by the synthesis. The override must be
non-empty and at most `MAX_TOOL_TEXT_CHARS` (1024) characters. `RESET` drops the
override and renders the formatted measurement again. Applied to every selected
directly addressable dimension.

Same rebuild/one-transaction/one-undo discipline; all-no-op is
`dimedit.unchanged` with no transaction. Refusals: `dimedit.payload`,
`dimedit.selection`, `dimedit.duplicate`, `dimedit.not_addressable`,
`dimedit.target_missing`, `dimedit.not_dimension`, `dimedit.bad_text`,
`dimedit.degenerate`.

**NOT IMPLEMENTED**: the `Home`/`New`/`Rotate`/`Oblique` extension-line edits;
only the text override is modelled on the entity.

### DIMOVERRIDE

`DIMOVERRIDE <variable> <value>` applies one variable to every selected
dimension's **entity style snapshot** (`DimensionStyleValues`), not to the
DIMSTYLE table. The closed admitted set is exactly the snapshot fields the
synthesis consumes:

`DIMTXT`, `DIMASZ`, `DIMEXO`, `DIMEXE`, `DIMGAP`, `DIMCEN`, `DIMDLI`, `DIMTAD`,
`DIMTVP`, `DIMLFAC`, `DIMDEC`, `DIMRND`, `DIMPOST`, `DIMZIN`, `DIMSE1`, `DIMSE2`,
`DIMSD1`, `DIMSD2`, `DIMDSEP`, `DIMLUNIT`.

Values are validated, never clamped:

* `DIMTAD` `0..=4`, `DIMDEC` `0..=8`;
* `DIMZIN` only `0`, `4`, `8`, `12` — the feet/inch zero-suppression bits 1/2
  are declared unimplemented by the formatter;
* `DIMLUNIT` only `2` (decimal); other formats are a declared degradation;
* `DIMDSEP` `0`, `46` or a printable ASCII code `32..=126`;
* numeric sizes/offsets: positive or non-negative as documented per variable;
  `DIMCEN`, `DIMTVP` finite; `DIMPOST` non-empty.

Recognised `DimStyle` variables not carried by the entity snapshot
(`DIMSCALE`, `DIMCLRD`/`DIMCLRE`/`DIMCLRT`, `DIMTXSTY`, `DIMJUST`, `DIMATFIT`,
`DIMTIX`, `DIMTOFL`, `DIMTIH`, `DIMTOH`, `DIMDLE`, `DIMCONTINUEMODE`) are
`dimoverride.unsupported_variable`; an unrecognised name is
`dimoverride.unknown_variable`; a malformed/out-of-range value is
`dimoverride.bad_value`, and an unimplemented value is
`dimoverride.unsupported_value`. Every refusal happens before any write.

All changed dimensions are rebuilt with the same definition/text override and
the mutated snapshot, then written in one transaction / one undo step. An
all-no-op run is `dimoverride.unchanged` with no transaction.

**NOT IMPLEMENTED**: DIMSTYLE-table overrides, persistent per-dimension override
records, and the variables listed as unsupported above.

### DIMREGEN

Payload-free. Reports `dimregen.non_associative` and changes nothing: this build
creates only non-associative dimensions, so there is no association to
regenerate. No revision bump, no `ChangeSet`, no history entry, no claim of an
update. A supplied payload is `dimregen.payload`. Viewer-legal.

### DIMDISASSOCIATE

Payload-free. Reports `dimdisassociate.already_non_associative` and changes
nothing. A supplied payload is `dimdisassociate.payload`. Viewer-legal.

### QDIM (v1, partial)

Payload-free; the current selection is the whole input. v1 supports **straight
`LINE` entities only** and produces one `DimensionKind::Aligned` dimension per
line:

* measured points = the line's start/end;
* dimension line = measured midpoint + left normal × the resolved `Standard`
  style's `DIMDLI` (default 3.75), so placement is style-driven and deterministic
  (there is no location prompt);
* measurement = the true endpoint distance, computed by the shared synthesis;
* non-associative, active layer, model space only;
* all dimensions are created in **one transaction / one undo step**.

Refusals (nothing written): `qdim.payload`, `qdim.selection`, `qdim.duplicate`,
`qdim.not_addressable`, `qdim.target_missing`, `qdim.space` (v1 creates in model
space only), `qdim.circle_unsupported`, `qdim.arc_unsupported`,
`qdim.point_unsupported`, `qdim.unsupported_kind` (named by geometry class),
`qdim.degenerate` (zero-length line), `qdim.no_style`, `qdim.bad_spacing`.

**NOT IMPLEMENTED**: AutoCAD's location prompt, radial/ordinate QDIM for
arcs/circles, chain/baseline arrangement in one QDIM run, and point input (a
lone point has no measurable extent and this build has no point ordering
primitive).

### DIMJOGLINE

The typed `ADD <x> <y>` / `REMOVE` grammar is modelled so the refusal can name
the real gap, but the command is an unconditional named refusal:

`dimjogline.unsupported` — `cad_domain::DimensionDefinition` has **no jog field**
and `DimensionGeometry` cannot store a jog. Nothing is read from the selection,
nothing is written, no history entry is opened. Bare `DIMJOGLINE` is
`dimjogline.needs_option`. Viewer-legal (it can never write).

### DIMBREAK

Payload-free (selection is the input). Unconditional named refusal:
`dimbreak.unsupported` — `DimensionGeometry` stores **no dimension-line break**
record. A supplied payload is `dimbreak.payload`. The command never deletes,
trims or shortens the dimension entity. Viewer-legal (it can never write).
