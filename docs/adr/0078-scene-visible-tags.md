# ADR-0078：场景可见标签（Scenes capture visible tags）

- 状态：**已接受（决策，2026-11-27）**；**已实现（2026-11-27，场景保存/恢复图层可见性；无真实 GUI/GPU 证据）**
- 关联：ADR-0063（场景表）、图层会话覆盖（`LAYEROFF`/`RestoreLayers`）、ADR-0065（文档显示记录）

## 背景

场景行此前只保存相机、2D/3D、工作平面、空间与 `WIREFRAME`/`SHADED` 样式；覆盖表明确写着
“不含可见 Tags/图层”。SketchUp 的页面会在恢复时把标签可见性一起带回，这是场景实际用途的
一部分（平面图/立面图各自隐藏不同图层）。

我们的图层可见性有两层：`cad-db` 图层表里的持久标志，以及会话 `LayerOverrideSet`
（`LAYEROFF`/`LAYERON`/`ISOLATEOBJECTS` 等产生的临时覆盖）。恢复场景不应改写图层表，因此
场景只保存**保存时的有效可见性**，恢复时把它落回会话覆盖。

## 决策

### D1 行快照（minor 23）

- `cad_domain::scene::Scene` 增加 `tags: Option<Vec<SceneTag>>`；`SceneTag { name, visible }`
  是**保存时的有效可见性**（图层表标志 + 会话覆盖），按图层表顺序保存全部图层。
- 行 JSON 只在有快照时写 `"tags": [{"name": ..., "visible": ...}]`；没有 `tags` 的旧行
  （minor 20..22）解码为 `None`，恢复时不碰图层可见性。
- 校验：最多 1024 行、名称 trim 后非空且 ≤255 字符、大小写不敏感唯一；违反是
  `scene.tags_invalid`，不写任何东西。
- 新行使归档升级到 **minor 23**（`FORMAT_MINOR = 23`）；无场景或旧场景行的文档仍按原档位写出。

### D2 恢复 = 会话覆盖

- `SCENE SAVE` 捕获每个图层的有效可见性。
- `SCENE RESTORE` 对每个保存的标签名在当前图层表中解析（精确优先，然后唯一大小写不敏感）：
  保存值与图层表标志相同 → **移除**会话覆盖；不同 → 设置覆盖。图层表本身从不改写，
  `SCENE RESTORE` 仍然不产生 revision/history（只有相机变化才记 `ZOOM PREVIOUS`）。
- 保存后新建的图层不在快照里，恢复时保持当前可见性；改名/删除的标签名被跳过，不伪造匹配。

### D3 边界

- 阴影、雾、剖面、软边**仍不随场景切换**：它们要么没有场景应用路径，要么需要文档写入。
- 没有“场景属性”复选框：本构建没有该 UI 模型，SAVE 总是捕获标签快照。
- 场景缩略图、逐场景动画/延迟仍不建模。

## 后果

- 场景行可携带标签快照；`tables/scenes.json` 的行格式向后兼容（旧行没有 `tags`）。
- 归档 minor 升到 **23**；旧读者按 `unsupported_minor` 拒绝带标签快照的新档，而不是静默丢失
  可见性。
- 覆盖表 Scenes 行从“不含可见 Tags”改为“保存/恢复可见 Tags”，其余未建模项照旧列出。
