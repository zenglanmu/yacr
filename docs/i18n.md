# 国际化（i18n）契约：简体中文 + 英文（N01）

本文档描述 `crates/cad-ui-slint/i18n/**` 与 `crates/cad-ui-slint/src/i18n.rs` 的
消息机制、key/占位符规则、回退策略与校验方式。需求来源：
`docs/code-audit-and-agent-handoff.md` §5（N01）、审计项 U10。

## 1. 单一真相（single source of truth）

- 翻译资源只有两份 JSON：`crates/cad-ui-slint/i18n/zh-CN.json` 与
  `crates/cad-ui-slint/i18n/en.json`。两文件使用**完全相同的 key 与占位符**。
- Rust 侧**不得再内嵌第二份用户可见文案**。`src/i18n.rs` 通过 `include_str!`
  读取 JSON 并在启动时解析成 `MessageCatalog`（不做逐帧解析）。
- `src/lib.rs` 里的 `ZH_CN_MESSAGES` 仅是 `i18n::ZH_CN_JSON` 的再导出别名，
  保留给打包/文档工具，不再是独立的翻译来源。
- 技术稳定标识（`CommandId`、diagnostic code、schema 字段、localStorage key）
  **不翻译**，见 §5 白名单。

## 2. Locale 解析与稳定取值

稳定 locale 见 `Locale` 枚举：

| `Locale` | `tag()` | 目录文件 |
|---|---|---|
| `Locale::ZhCn` | `zh-CN` | `zh-CN.json` |
| `Locale::En` | `en` | `en.json` |

`resolve_locale(tag)` 返回 `LocaleResolution { requested, locale, fallback }`：

- 输入按首个 `-`/`_` 主语言子标签小写化匹配；主标签缺失或非纯字母 → `Malformed`。
- `zh`/`en`（含大小写、地区、书写系统变体）→ 归一化到对应 `Locale`。
  例：`en-US`、`en_US`、`EN-us`、`zh-Hans-CN`、`zh_CN` 均可接受。
- 主标签无目录（`de`、`ja-JP`…）→ 回退 `zh-CN`，原因 `Unsupported`。
- 空串、`-`、`--`、`123` → 回退 `zh-CN`，原因 `Malformed`。
- `fallback` 为 `None` 表示请求标签与稳定 tag **逐字符相等**（大小写敏感）；
  仅大小写/地区差异时记 `Normalised`。这样宿主可区分“本来就要 en”与
  “要 en-US 结果拿到 en”。
- 默认 locale 为 `zh-CN`（`DEFAULT_TAG`，`UiConfiguration::default` 亦如此）。

**可诊断策略**：`UiAdapter::new` 在解析出 `fallback` 时用 `log::info!` 记录
`requested`、实际 `locale` 与原因；`UiHandle::set_locale` 把 `LocaleResolution`
返回给宿主，宿主可自行提示或持久化。

## 3. 缺 key 行为

`MessageSource::message(key, args)` 返回 `Message`：

- `Message::Found(text)`：命中的格式化文本。
- `Message::Missing(key)`：目录中没有该 key。

`Message::text()` 对缺失 key 返回 `⟦key⟧`（U+27E6/U+27E7 包裹），**绝不返回空串**，
使缺翻译在截图/日志中立刻可见。未知占位符同理保留 `{name}` 原文，便于发现拼写错误。

`MessageSource` 支持运行时切换：`set_locale(tag)` 重建目录并返回
`LocaleResolution`；UI/宿主持有它即可重建可见文案（保持文档、相机、选择与撤销栈
不变 —— 见 §6 未完成项）。

## 4. key 与占位符规则

- key 形如 `area.item`：小写字母开头，点分层级，段内 `[a-z0-9_]`。
- 占位符为 `{name}`，`name` 为 `[A-Za-z_][A-Za-z0-9_]*`。
- 占位符集合在两种语言中必须**顺序一致、集合一致**（脚本按集合比较）。
- `\{` 为字面 `{` 的转义。
- 数值格式化（长度/角度/面积、decimal_places、未知单位文案）属于显示层，
  N01 只要求“未知单位为中文‘图纸单位’/英文‘Drawing units’”；机器 JSON 数值
  保持 locale 无关（见 §6）。

## 5. 校验：`scripts/check-i18n.py`

纯标准库脚本，任一失败即非零退出（供 `i18n-contracts` CI job 使用）：

1. 两份目录均需存在、为扁平 JSON 对象且值非空字符串；
2. 目录不能为空；
3. key 集合完全一致（多/少/空 key 均报错）；
4. 同名 key 的 `{placeholder}` 集合一致；
5. Rust 中 `.text("a.b")`/`.message("a.b")` 引用的 key 必须存在于目录。

第 5 条为 best-effort：脚本用 `KEY_SHAPE_RE` 只挑点分形态的字面量，并对
非翻译的稳定标识维护**显式白名单**（`ALLOWLIST`，附注释）。新增动态/非文案引用时
应加入白名单并说明，而不是放宽整条规则。

## 6. 有意尚未完成（依赖其他工作流，勿在此宣称完成）

以下是 N01 的其余部分，**本工作流（catalog/core 层）不负责**，需 ui3d / host 工作流：

- **完整 UI chrome 翻译**：`ui/app.slint` 中仍有硬编码中文（“适应/撤销/重做/导出/
  导入/诊断”、`mode-label`、96px 后端框、28px 状态栏）。切换应改为从 `MessageSource`
  驱动属性，并在英语长文案下做布局/工具提示覆盖。
- **HTML/JS locale 同步**：`apps/app-web/web/index.html` 的 `lang`/`title`/
  `noscript` 与 `main.js` 的启动/文件提示尚未与当前语言同步，也未由构建生成共享
  catalog。
- **偏好持久化**：语言选择未写入 localStorage/宿主偏好，重启不恢复；设置页
  “简体中文 / English”尚未实现。
- **JS 提示与宿主诊断的双语**：`apps/**` 与 `crates/cad-app` 的 `last_status`、
  diagnostic message 目前为中文；应改为结构化 code + 参数、由表现层本地化。
- **数值/单位本地化**：仅 `units.unknown` 已建模，长度/角度/面积与 `decimal_places`
  尚未按语言格式化。

以上未完成项不应以“新增了 `en.json`”为由标记为完成；它们需要 ui3d/host 工作流的
实际接线与验收测试。
