# 国际化（i18n）契约：简体中文 + 英文（N01）

本文档描述**当前**的消息机制、key/占位符规则、回退策略与校验方式。需求来源：
`docs/code-audit-and-agent-handoff.md` §5（N01）、审计项 U10。

> **2026-10-16 变更**：Slint 桌面退役后，**唯一权威目录**是
> `crates/cad-ui-core/i18n/{zh-CN,en}.json`；机制从 `cad-ui-slint/src/i18n.rs` 迁到
> `crates/cad-ui-core/src/i18n.rs`。旧 `cad-ui-slint` 目录与其重复副本已删除。校验脚本
> `scripts/check-i18n.py` 同时覆盖 Rust 与 React 宿主。见 ADR 0010。

## 1. 单一真相（single source of truth）

- 翻译资源只有两份 JSON：`crates/cad-ui-core/i18n/zh-CN.json` 与
  `crates/cad-ui-core/i18n/en.json`。两文件使用**完全相同的 key 与占位符**。
- Rust 侧**不得再内嵌第二份用户可见文案**。`crates/cad-ui-core/src/i18n.rs` 通过 `include_str!`
  读取 JSON 并在启动时解析成 `MessageCatalog`（不做逐帧解析）。
- **React 侧**经 Vite `@i18n` 别名读取同一份目录（`apps/desktop-ui/vite.config.mjs`），
  `src/i18n.ts` 的 `t(key, params)` 仅在缺失 key 时回退（回退到默认语言，再回退到 key 本身）。
- 技术稳定标识（`CommandId`、diagnostic code、schema 字段、localStorage key）**不翻译**，见 §5 白名单。

## 2. Locale 解析与稳定取值

稳定 locale 见 `cad_ui_core::i18n::Locale` 枚举：

| `Locale` | `tag()` | 目录文件 |
|---|---|---|
| `Locale::ZhCn` | `zh-CN` | `zh-CN.json` |
| `Locale::En` | `en` | `en.json` |

`resolve_locale(tag)` 返回 `LocaleResolution { requested, locale, fallback }`：输入按首个 `-`/`_`
主语言子标签小写化匹配；`zh`/`en`（含大小写、地区、书写系统变体，如 `en-US`、`zh-Hans-CN`）归一化
到对应 locale；无目录主标签（`de`、`ja-JP`…）或畸形输入（``、`-`、`123`）回退 `zh-CN` 并记录原因；
`fallback` 为 `None` 表示请求标签与稳定 tag 逐字符相等。默认 locale 为 `zh-CN`。

**可诊断策略**：解析出 `fallback` 时记录 `requested`/实际 `locale`/原因；语言切换只重建 chrome，
不重建文档、相机、选择与撤销栈。

## 3. 缺 key 行为

`MessageSource::message(key, args)` 返回 `Message::Found(text)` 或 `Message::Missing(key)`；
`Message::text()` 对缺失 key 返回 `⟦key⟧`（U+27E6/U+27E7 包裹），**绝不返回空串**；未知占位符
保留 `{name}` 原文。React 侧同理：缺失 key 返回 key 本身。`MessageSource` 支持运行时切换
（`set_locale(tag)` 重建目录并返回 `LocaleResolution`）。

## 4. key 与占位符规则

- key 形如 `area.item`：小写字母开头，点分层级，段内 `[a-z0-9_]`。
- 占位符为 `{name}`，`name` 为 `[A-Za-z_][A-Za-z0-9_]*`。
- 占位符集合在两种语言中必须**一致**（脚本按集合比较）。
- `\{` 为字面 `{` 的转义。
- 数值格式化（长度/角度/面积、decimal_places、未知单位文案）属显示层；N01 只要求“未知单位为
  中文‘图纸单位’/英文‘Drawing units’”，机器 JSON 数值保持 locale 无关。

## 5. 校验：`scripts/check-i18n.py`

纯标准库脚本，任一失败即非零退出（`i18n-contracts` CI job）：

1. 两份目录均需存在、为扁平 JSON 对象且值非空字符串；目录不能为空；
2. key 集合完全一致（多/少/空 key 均报错）；
3. 同名 key 的 `{placeholder}` 集合一致；
4. **静态引用的 key 必须存在**：Rust `.text("a.b")`/`.message("a.b")`/`format!("a.b")` 与
   catalog-key `const`（如 `const KEY_OPEN: &str = "file.open"`）；React `t('key')`/`t("key")`
   与静态 `labelKey`/`titleKey` 表项。对非翻译的稳定标识维护**显式白名单**（`ALLOWLIST`，附注释）；
   新增动态/非文案引用应加入白名单并说明，而不是放宽整条规则。
5. **非测试 Rust 源码不得出现硬编码 CJK**；
6. **React JSX/JS 源码不得出现硬编码 CJK**：对 `apps/desktop-ui/src` 的 `*.jsx`/`*.js`/`*.mjs`
   做受限词法扫描，跳过注释；字符串/模板字面量与裸 JSX 文本节点中的 CJK 报错。

脚本可接受可选 workspace root（`python3 scripts/check-i18n.py [root]`），供负向/正向契约测试
用临时 fixture 调用；负向/正向控制见 `scripts/test-ui-migration-guards.py`。

**诚实限制**：只解析**字面量** key；经间接（如 `t(item.labelKey)` 运行时组装）的 key 不在本脚本
覆盖范围内，仍由 React 的 `ui/test/i18n.test.ts` 与评审兜底。React CJK 扫描是**词法启发式而非
完整解析器**，同时存在误报（模板插值内注释中的 CJK 会被当作模板内容）与漏报（含 `//`/`/*` 的
正则字面量被误判为注释）的可能；脚本对“拒绝什么”保守，但不精确。

## 6. 宿主接线状态

- **Rust 侧（`cad-ui-core`）**：目录 + 解析 + 回退 + `MessageSource` 运行时切换；`check-i18n.py`
  扫描 Rust 源与 React 源，禁止硬编码 chrome 文案。
- **React 侧（`apps/desktop-ui`）**：所有可见文案经 `t(key, params)` 从 `@i18n` 目录读取；
  角落语言切换（简体中文 / English）已接线；`ui/test/i18n.test.ts` 断言目录完整、占位符平衡、
  字面量 key 存在。

### 仍未完成（勿宣称完成）

- **运行时语言切换不重排 Rust 宿主的宿主侧字符串**：宿主启动时读一次 `YACR_LOCALE`；
  Rust 侧的状态/诊断文案切换后不会重排。
- **数值/单位本地化**：仅 `units.unknown` 已建模；长度/角度/面积与 `decimal_places` 尚未按语言格式化。
- **动态 key 覆盖**：`check-i18n.py` 不解析运行时组装的 key（见 §5 限制），依赖 React 测试兜底。

以上未完成项不应以“新增了 `en.json`”为由标记为完成。
