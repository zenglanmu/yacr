# 2026-11-07 draw/modify batch: DONUT/SOLID/HELIX/MLINE/MLSTYLE/TREX/EXTRIM/MPEDIT/DRAWORDER

Status: **partial, contract-level only**. Ten AutoCAD-2026 2D draw/modify
selectors are wired end to end (CommandId → `COMMAND_TABLE` → `Application::execute`
→ work-mode capability → UI catalog/gating → i18n → ribbon where a button is a
real affordance), with one transaction / one undo step per write and named
refusals before any transaction opens.

This file is the batch record. It deliberately does **not** edit
`docs/compatibility.md`, `docs/handoff.md` or
`docs/autocad-2026-command-coverage.md` (owned by other lanes).

## Shared facts

- Every creating command goes through the existing create funnel
  (`commit_new_entities` / `commit_new_entity_typed`).
- Every editing command plans all work first, then stages the whole plan in one
  `begin_drawing_transaction` and publishes one `DrawingUndoRecord`.
- `MLSTYLE` writes no drawing data: it maintains the session-only
  `MultilineStyleStore` (cap **16**) that `MLINE` reads.
- `-OVERKILL` is a `COMMAND_ALIASES` row onto the existing `OVERKILL`
  `CommandId`/planner — not a second dedupe implementation and not a second
  `COMMAND_TABLE` row (the vocabulary contract requires one row per CommandId).
- `Rw` = one transaction / one undo step. All refusals happen before it opens.

## Command boundaries

### DONUT

- Payload `Draw2Payload::Donut { center, inner, outer }`.
- Command-line form in this build: `DONUT <cx> <cy> <inner> <outer>`. There is
  no centre pick prompt, so the declared AutoCAD two-number form
  (`DONUT <inner> <outer>`) is **not** available on the command line; the
  payload/API form is complete.
- Refusals: `donut.payload`, `donut.invalid_point`, `donut.invalid_radius`
  (`inner < 0` or non-finite), `donut.radius_order` (`outer <= inner`).
- `inner == 0`: a zero-radius circle is not representable, so only the outer
  circle is stored and `donut.inner_zero` is reported. Declared partial result,
  not a fake second entity.
- **NOT IMPLEMENTED**: FILL mode / donut width semantics, picking an existing
  donut, a centre pick prompt.

### SOLID

- Payload `Draw2Payload::Solid { points }` with 3 or 4 ring-ordered points.
- Command-line form: `SOLID <x,y> <x,y> <x,y> [<x,y>]`.
- Representation is `SemanticGeometry::Mesh` — the same filled-face shape the
  importer's SOLID/TRACE and 3DFACE paths use — with triangles `[0,1,2]` (3
  points) or `[0,1,2]` + `[0,2,3]` (4 points), computed vertex normals and no
  colours. Stored type key `AcDbSolid`.
- Refusals: `solid.payload`, `solid.point_count`, `solid.invalid_point`,
  `solid.not_planar`, `solid.duplicate_point`, `solid.self_crossing`,
  `solid.zero_area`.
- **Loss on export**: the DXF exporter writes any `Mesh` as a `PolyfaceMesh`, so
  a SOLID round-trips as a polyface mesh, not a SOLID record.
- **NOT IMPLEMENTED**: thickness/elevation, a 3D solid, edge/face editing.

### HELIX

- Payload `Draw2Payload::Helix { base, radius, turns, height }`.
- Command-line form: `HELIX <base x> <base y> <radius> <turns> <height>`.
- Geometry: one open `Polyline` in the base point's XY plane; radius grows
  linearly from 0 to `radius` over `turns` revolutions, sampled at 64 segments
  per turn and bounded to 4096 vertices.
- `height == 0` is the implemented flat spiral. `height > 0` is the 3D spring,
  which is refused as `helix.3d_not_implemented` rather than silently flattened.
- Refusals: `helix.payload`, `helix.invalid_point`, `helix.invalid_radius`,
  `helix.invalid_turns`, `helix.invalid_height`.
- **NOT IMPLEMENTED**: 3D spring, top/bottom radius pair, axis point, twist
  direction, a true `AcDbHelix`/spline entity.

### MLINE

- Payload `Draw2Payload::Mline { spacing, offset, points }` with exactly two
  baseline points. `spacing: None` uses the current `MLSTYLE` spacing; an
  explicit value overrides it for that invocation.
- Command-line form: `MLINE <spacing> <offset> <x1,y1> <x2,y2>`.
- Writes exactly **two** parallel `Line` entities at `±spacing/2 + offset`
  measured along the baseline's XY normal, one undo step.
- Refusals: `mline.payload`, `mline.point_count`, `mline.invalid_point`,
  `mline.degenerate_baseline`, `mline.invalid_spacing`, `mline.invalid_offset`.
- **NOT IMPLEMENTED**: joins, caps, miters/bevels, an element table, multi-segment
  baselines, a real `AcDbMline` entity. This is a declared partial MLINE.

### MLSTYLE

- Payload `Draw2Payload::MlStyle(List | Set { name, spacing })`.
- Command line: `MLSTYLE LIST` / `MLSTYLE SET <name> <spacing>`.
- Session-only `MultilineStyleStore` (default `STANDARD` at spacing 1.0, cap 16);
  the current style feeds `MLINE`. No drawing revision, no undo entry, no DWG
  persistence; Viewer mode is allowed.
- Refusals: `mlstyle.payload`, `mlstyle.invalid_name`,
  `mlstyle.invalid_spacing`, `mlstyle.capacity`.
- **NOT IMPLEMENTED**: DWG MLSTYLE records, element tables, caps/joins,
  linetypes/colours.

### TREX

- Payload `Draw2Payload::Trex(Trim | Extend)`; the current selection is the
  input. Every selected model-space object is a target; every *other* selected
  object is a boundary.
- No boundary pick prompt: TRIM keeps the piece containing each target's
  parametric midpoint (`u = 0.5`); EXTEND grows the target's `u = 1` end. This is
  a declared deterministic divergence.
- Reuses `plan_trim` / `plan_extend` and `collect_boundaries` (no second trim
  implementation). A plan-level target refusal is a per-target `trex.skipped`
  diagnostic; an unsupported boundary kind refuses the whole command.
- One transaction / one undo step for all changed targets. Refusals:
  `trex.payload`, `trex.selection` (< 2), `trex.not_addressable`,
  `trex.unsupported_boundary`, `trex.unsupported_target`.

### EXTRIM

- Payload `Draw2Payload::Extrim { boundary, targets }`; bare selector with no
  payload uses the current selection: **first selected = boundary**, rest =
  targets (declared choice).
- Supported boundary kinds are the trim collector's set: LINE/CIRCLE/ARC/
  POLYLINE (and the other primitives it already accepts); an unsupported kind is
  `extrim.unsupported_boundary`. Supported target kinds are LINE/ARC/CIRCLE/
  SPLINE; others are `extrim.unsupported_target`.
- Each target is trimmed with the existing `plan_trim`, keeping the piece
  containing its parametric midpoint. Targets with no crossing are
  `extrim.skipped`; all real changes are one transaction / one undo step.
- Refusals: `extrim.payload`, `extrim.selection`, `extrim.not_addressable`,
  `extrim.boundary_is_target`, `extrim.unsupported_boundary`,
  `extrim.unsupported_target`.

### MPEDIT

- Payload `Draw2Payload::Mpedit(PeditOption)`; command line
  `MPEDIT CLOSE|OPEN|REVERSE` (letters `C/O/R`).
- Every selected, directly addressable model-space LWPOLYLINE is changed in one
  transaction / one undo step. Non-polylines are per-entity `mpedit.skipped`
  diagnostics; an already-in-state polyline is `mpedit.unchanged`; degenerate
  CLOSE targets are skipped by name. With no eligible change the command is an
  `mpedit.nothing_changed` no-op (no transaction).
- Refusals: `mpedit.payload`, `mpedit.selection`.
- **NOT IMPLEMENTED**: PEDIT JOIN/WIDTH/FIT/SPLINE/etc. (same subset as PEDIT).

### DRAWORDER

- Payload `Draw2Payload::DrawOrder(Front | Back | Above | Below)`; command line
  `DRAWORDER FRONT|BACK|ABOVE|BELOW`.
- `FRONT`/`BACK`: move the whole selection above/below every non-selected
  model-space row, preserving the selection's relative order.
- `ABOVE`/`BELOW`: the **first selected** object is the reference, the rest is
  the moving set. The moving set is placed immediately above/below the reference;
  already-occupying rows on that side are shifted by the needed amount in the same
  transaction, so relative order is preserved and no rows silently swap.
- Refusals: `draworder.payload`, `draworder.selection`, the named
  `draworder.reference_required` (ABOVE/BELOW with < 2 selected),
  `draworder.not_addressable`, `draworder.order_exhausted`.
- **NOT IMPLEMENTED**: paper-space/block draw order, a Draw Order dialog, a
  separate reference-object prompt.
