# 批注文件持久化审查（2026-10-04）

## 范围与依据

仅修改 `crates/cad-annotations` 的侧车编码、导出确认与公共契约测试。
依据 `CAD_IMPLEMENTATION_SPEC.md` §3.4：导出成功后才标记已保存，
损毁与未知字段不得静默丢失。已阅读 `docs/annotations.md` 和
`docs/review-branches.md`；不重复上一轮仿射方向向量、矩阵校验修复。

## 三项修复

1. 解码已拒绝重复批注 ID，但编码此前允许输出自身无法重新读取的文件。
   编码现在先检查 ID 唯一性，重复返回 `InvalidInput`，导出不清除 dirty。
2. `export_sidecar` 此前将任意调用方文件绑定到调用时数据库 revision，
   即使文件是旧快照、空文件、漏项或包含其他批注，也可能错误标记已保存。
   现在编码成功后、确认保存前，要求批注数量与逐 ID 内容完全匹配数据库。
   顺序不要求一致；不匹配返回 `InvalidInput`，不修改内容、revision 或 dirty。
   独立 `encode` 仍允许构造与数据库无关的有效侧车。
3. `extensions_json` 中的 `yacr.nested_extensions` 此前被直接跳过，
   合法或损毁的原始边带都可能在成功导出时消失。现在拒绝这一保留键，
   要求调用方使用现有类型化 `nested_extensions`。正常解码早已移除原始键，
   因而正常解码后重编码路径不受影响；不引入新格式或字段。

## 回归契约与证据

新增 **4 项合成集成测试**（`tests/codec_contracts.rs`）：重复编码/导出失败、
旧或不完整快照失败且可恢复到成功导出、乱序等价快照成功、原始保留边带拒绝。
失败用例检查 dirty、revision 和既有内容不变。

**NOT RUN**：本子代理未执行编译、测试、静态检查或格式化，未提交或推送；
统一 debug 编译与验证由主控合并后执行。没有真实文件系统原子写入、
真实 DWG、GPU、宿主平台或用户数据验收证据。

## 风险与未覆盖

- `export_sidecar` 对调用方快照的要求收紧；刻意导出批注子集的调用方应使用
  `encode`，不得借此确认整库已保存。
- 私有原始边带手工构造者现在明确报错，而不是自动迁移或忽略。
- 快照比较只覆盖本层拥有的数据库批注，不验证宿主文档身份、实际磁盘写入
  或持久化完成；宿主仍必须使用 `encode` 加成功写入后的 revision 确认。
- 未新增迁移、指纹策略、重复 JSON 对象键检测或更广泛的数值校验；
  不把这些未审查路径声称为已完成。
