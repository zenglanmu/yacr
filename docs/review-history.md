# Rust 审查：历史栈一致性（2026-10-04）

本轮重点审查 `cad-db` 的批注原子写入与 `cad-history` 的撤销/重做边界，
并阅读 `cad-app` 调用点；不是全仓库逐文件审计，也不宣称产品验收完成。

## 已修复

- **批注撤销/重做失败丢记录**：原实现先弹栈，再调用可能失败的数据库写入。
  改为先借用栈顶构造变更，数据库接受后才移动记录与重做标记、调整字节计数。
  回归覆盖失败后 revision、栈深度、计数不变，以及修复数据库状态后可以重试。
- **UUID 被当成内存字节数**：删除 `p.id.0 as usize`；标识已包含在结构体大小中。
  极大 ID 原本会触发 debug 整数溢出，普通随机 UUID 也会造成无意义淘汰。
  回归使用 `u128::MAX` 检查批注/绘图估算与 ID 数值无关。
- **绘图标记计数不对称**：入栈计入标记和 payload，待提交步骤保留原标记；
  完成/取消/重做都恢复同一个标记，避免丢失事务身份、标签和估算大小。
  回归覆盖完整往返、取消以及预算淘汰后共享栈与绘图 payload 一一对应。
- **合并绕过预算**：合并后重新估算并执行与普通记录相同的淘汰逻辑。
- **待提交绘图步骤被覆盖**：`begin_drawing_*`、`record*` 和批注 `undo/redo`
  在已有待提交步骤时显式拒绝，必须先完成或取消；`clear` 仍显式清空整个历史。
- **批注伪装绘图标记**：拒绝批注记录使用保留的 `__drawing__` 合并键，
  避免无绘图 payload 的记录进入绘图分派路径。
