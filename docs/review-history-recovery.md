# 历史恢复路径审查（2026-10-04）

范围仅为 `crates/cad-history` 的 `RecoveryJournal` / `MemoryJournal`；遵循
`CAD_IMPLEMENTATION_SPEC.md` §4.7、§16.3，未重复先前合并消去、payload 校验或
撤销/重做栈原子性修复。没有修改其他 crate 或共享交接文档。

## 修复

1. **日志接受无效记录并可能产生空成功**：`append` 原来无条件复制记录，空 patch、
   重复 ID、快照身份不匹配、两侧不存在及绘图占位标记均可进入批注恢复日志。
   现复用已有 `UndoRecord::validate`，失败时不追加，不影响先前记录。这里只检查
   记录结构；几何等数据库语义仍由真实数据库写入路径验证。
2. **恢复失败泄漏已重放前缀**：原来逐条直接修改目标数据库，后续删除不存在的
   批注或非法几何导致返回错误时，之前记录已修改数据与 revision，却没有返回其
   ChangeSet。现将整批重放到临时数据库副本，全部成功后才替换目标并返回逐条
   ChangeSet；失败时数据、数据库身份、revision 与导出/dirty 状态保持原样。
   空日志直接返回空集合，不复制数据库；这是明确的无记录路径，而非吞掉失败。

## 新增合成回归

共 **4 项**：

- 无效追加的六种结构输入、已有记录保留及后续合法恢复。
- 后续删除失败保持已导出状态，补齐缺失数据后可重试，并检查 revision 链与事务身份。
- 后续非法几何失败不发布前面的更新，保持原数据、revision 与 dirty 状态。
- 顺序创建/删除成功恢复与空日志无变化，检查逐条 ChangeSet 和最终状态。

## 边界与风险

- 临时克隆开销随目标批注库大小增长；没有在历史中保留全库副本，也没有新增无限
  快照保留策略，但本轮未做内存/性能测量。整批成功时替换数据库实例的值，公开
  API 与逐条 revision/ChangeSet 语义保持不变。
- 仍是内存合成恢复日志，不是持久化或版本化崩溃恢复实现；未新增数据库身份绑定、
  before 快照冲突检测、幂等恢复或绘图日志支持，也不声称上述能力完成。
- 返回的错误仍来自现有验证路径，不将失败转换为空成功；失败不清理恢复记录。
